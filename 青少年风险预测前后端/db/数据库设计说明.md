## 一、总览

数据库 `youth_ideology` 服务于「青少年意识形态风险识别平台」，围绕**四库中枢**（标签体系 / 语料 / 案例 / 话术）+ **三级分类体系** + **风险域词库** + **运行时研判记录**四类构成。

### 表间关系概览

四库以 **`t_risk_label`（标签体系）为中枢**，通过业务字段软关联（无物理外键）：

- **标签体系 → 语料**：`t_corpus.tag_id` 命中 `t_risk_label.tag_id`，继承其风险域 / 二级类型 / 三级标签编码 / 综合风险分。
- **语料 → 案例**：同主题高互动语料聚类为 `t_case`，`t_case.representative_corpus_id → t_corpus`、`related_tag_id → t_risk_label`。
- **案例 → 话术**：`t_ai_script.related_case_id → t_case`、`related_tag_id → t_risk_label`，按年龄段配引导话术。
- **分类字典**：`t_corpus / t_risk_label` 的 `l1/l2/l3_tag_code` 对应三级分类字典；层级 `t_l3_taxonomy.l2_code → t_l2_taxonomy.l1_code → t_l1_taxonomy`。
- **四库关系表**：`t_lib_relation` 以「(主体类型,主体ID) - 关系 - (客体类型,客体ID)」记录语料↔标签↔案例↔话术的任意关联。
- **风险域词库**：`t_domain_keyword` / `t_domain_template` 用于识别阶段的关键词与句式召回，独立于四库。
- **运行时链路**：`t_dialog_record`（用户输入）→ `t_risk_assessment`（评估，`dialog_id` 关联）→ `t_guidance_response`（分龄话术响应 + 反馈，`selected_script_id → t_ai_script`）。

**核心数据流**：采集内容按 `search_keyword/matched_keyword` 命中 `t_risk_label` 的关键词 → 继承该标签的风险域/二级类型/L1–L3 编码/综合风险分，写入 `t_corpus`；高互动、同主题语料聚类形成 `t_case`；案例按年龄段配 `t_ai_script` 话术。运行时用户内容进入 `t_dialog_record` → 评估落 `t_risk_assessment` → 匹配话术落 `t_guidance_response`。

## 二、四库核心

### 1. `t_risk_label` — 语料标签体系（规则 + 关键词库）

**定位**：全库中枢。把「关键词 → 风险域 / 二级类型 / 三级标签 / 风险分 / 引导方向」的业务规则固化为一张表，供语料标注、案例归类、话术调用统一引用。

**关键字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| `tag_id` | varchar(20) PK | 标签编号（如 TAG-00001） |
| `keyword` | varchar(100) | 触发关键词 |
| `risk_domain_l1` | varchar(50) | 一级风险域（制度认同/历史认知/心理韧性/认知闭合/网络素养） |
| `risk_type_l2` | varchar(100) | 二级风险类型 |
| `applicable_scenario` | varchar(100) | 对应场景 |
| `dimension` | varchar(100) | 对应维度（旗帜/道路/人心向背/政治安全…） |
| `opposition_level` | char(1) | 对立等级（A 高 / B 中 / C 低） |
| `content_nature` | varchar(10) | 内容性质（C1–C4） |
| `group_opposition_threshold` | varchar(10) | 群体对立阈值（V1–V4） |
| `content_risk_score` / `opposition_risk_score` / `opposition_level_score` / `total_risk_score` | decimal(6,2) | 内容分 / 对立分 / 对立等级分 / **综合风险分** |
| `l1_tag_code`+`l1_tag_desc` / `l2_…` / `l3_…` | varchar | 三级标签编码与说明（L1-xx / L2-xx / L3-xx） |
| `guidance_direction` | varchar(500) | 建议引导方向 |
| `tag_chain` | varchar(200) | 标签链（风险域 / 二级类型 / L1-L2-L3） |

**索引**：主键 `tag_id`；`keyword`、`risk_domain_l1`、`total_risk_score` 普通索引；`keyword` 全文索引。
**被引用**：`t_corpus.tag_id`、`t_case.related_tag_id`、`t_ai_script.related_tag_id`。

### 2. `t_corpus` — 语料库

**定位**：多平台采集的内容 + 风险标注主表，是账号画像与批量态势看板的数据源。

**关键字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| `corpus_id` | varchar(30) PK | 语料编号（COR-xxxxxx） |
| `platform` | varchar(30) | 平台（微博/抖音/小红书/百度） |
| `search_keyword` / `matched_keyword` | varchar(200) | 采集搜索词 / 命中关键词 |
| `tag_id` | varchar(20) | 命中标签 → `t_risk_label` |
| `risk_domain_l1` / `risk_type_l2` | varchar | 一级风险域 / 二级类型（随标签继承） |
| `risk_level` | varchar(10) | 风险等级（低/中/高/极高） |
| `total_risk_score` / `content_risk_score` / `opposition_risk_score` | decimal(6,2) | 综合 / 内容 / 对立风险分 |
| `l1_tag_code` / `l2_tag_code` / `l3_tag_code` | varchar(20) | 命中三级标签编码 |
| `guidance_direction` / `tag_chain` | varchar | 引导方向 / 标签链 |
| `title` / `content_summary` / `full_text` | varchar/text/longtext | 标题 / 摘要 / 正文 |
| `author` / `publish_time` / `url` | | 作者 / 发布时间 / 链接 |
| `like_count`/`comment_count`/`share_count`/`collect_count`/`interaction_count` | int | 点赞/评论/转发/收藏/总互动 |
| `is_case_candidate` | tinyint | 是否进入案例候选 |
| `desensitize_status` / `review_status` | tinyint | 脱敏 / 复核状态 |
| `source_file` | varchar(200) | 原始来源文件 |

**索引**：主键 `corpus_id`；`tag_id`、`platform`、`risk_level`、`total_risk_score`、`publish_time` 普通索引；`title,content_summary` 全文索引。

### 3. `t_case` — 案例库

**定位**：由同主题、高互动语料聚类而成的典型案例，附传播机制研判与分龄处置策略。

**关键字段**：`case_id`(PK)、`case_name`、`related_tag_id`→标签、`representative_corpus_id`→语料、`related_script_id`→话术、`platform`、`risk_level`、`related_corpus_count`（关联语料数）、`total_interaction`（总互动）、`avg_risk_score`、`case_priority_score`（优先级）、`representative_text`（代表文本）、`spread_mechanism`（传播机制）、`disposal_strategy_platform/6_12/13_15/16_18`（平台+三年龄段处置策略）、`review_conclusion`（复盘结论）。
**索引**：主键 + `related_tag_id`、`risk_domain_l1`、`risk_level`、`case_priority_score`；`case_name,core_keywords,representative_text` 全文索引。

### 4. `t_ai_script` — AI 话术库

**定位**：面向 6–12 / 13–15 / 16–18 三个年龄段的引导话术，按风险域、类型、等级、平台检索调用。

**关键字段**：`script_id`(PK)、`related_case_id`→案例、`related_tag_id`→标签、`risk_domain_l1`/`risk_type_l2`、`core_keywords`、`applicable_platform`、`age_group`（年龄段）、`applicable_risk_level`、`script_type`（话术类型）、`script_phase`（话术阶段）、`trigger_condition`（触发条件）、`script_content`（话术正文）、`follow_up_action`（后续动作）、`use_count`/`effective_rate`（使用量/有效率）。
**索引**：主键 + `related_tag_id`/`risk_domain_l1`/`age_group`/`applicable_risk_level`/`review_status`，组合索引 `(risk_domain_l1,age_group,applicable_risk_level)` 供分龄检索；`core_keywords,trigger_condition,script_content` 全文索引。

## 三、三级分类体系（字典表）

风险分类的标准字典，L1→L2→L3 逐级归属；供标注、检索、看板归类使用。

- **`t_l1_taxonomy`**：`l1_code`(PK)、`l1_name`、`sort_order`。一级风险域字典（16 条）。
- **`t_l2_taxonomy`**：`l2_code`(PK)、`l2_name`、`l1_code`（归属 L1）、`sort_order`（34 条）。
- **`t_l3_taxonomy`**：`l3_code`(PK)、`l3_name`、`l2_code`（归属 L2）、`sort_order`（50 条）。

> 层级：`t_l3_taxonomy.l2_code` → `t_l2_taxonomy.l2_code`；`t_l2_taxonomy.l1_code` → `t_l1_taxonomy.l1_code`。

## 四、风险域词库（识别召回，独立于四库）

- **`t_domain_keyword`**（255 条）：`id`(PK 自增)、`domain_code`/`domain_id`/`domain_name`（风险域）、`cluster`（聚类）、`keyword`（关键词）。用于内容识别阶段的五大风险域关键词召回。
- **`t_domain_template`**（40 条）：`id`(PK 自增)、`domain_code`/`domain_id`/`domain_name`、`template_code`、`pattern`（句式模板）、`risk_action`（风险动作）。用于句式模式匹配召回。

## 五、运行时研判记录（预留，随插件/后台运行写入）

一次「用户内容 → 评估 → 引导」的完整链路记录，当前为空表，上线后由服务写入。

- **`t_dialog_record`**（对话/内容输入）：`dialog_id`(PK)、`session_id`、`platform`、`user_id`、`age_group`、`content`（内容）、`content_type`、`input_time`、`channel_source`、`extra_data`(json)、`process_status`。
- **`t_risk_assessment`**（风险评估结果）：`assess_id`(PK)、`dialog_id`→对话、`matched_tag_ids`(json)、`matched_keywords`、`risk_domain_l1`/`risk_type_l2`/`risk_level`、`total/content/opposition_risk_score`、`hit_l1_codes`/`hit_l2_codes`/`hit_l3_codes`（命中三级编码）、`assess_method`（rule/llm）、`assess_detail`(json)、`assess_time`。
- **`t_guidance_response`**（引导响应与反馈）：`response_id`(PK)、`dialog_id`、`assess_id`、`candidate_script_ids`(json)、`selected_script_id`→话术、`script_content`、`age_group`、`is_ai_rewrite`（是否 AI 改写）、`feedback_score`/`feedback_label`/`feedback_time`（反馈）。

## 六、迁移注意事项

1. **排序规则**：建表脚本使用 MySQL 8.0 默认的 `utf8mb4_0900_ai_ci`。迁移到 **MySQL 5.7 / MariaDB** 时需全局替换为 `utf8mb4_unicode_ci`，否则报「Unknown collation」。
2. **仅结构 vs 含数据**：`schema.sql` 只建结构。迁数据用 `mysqldump -u root -p --default-character-set=utf8mb4 youth_ideology > full.sql`。
3. **执行顺序**：脚本每张表前有 `DROP TABLE IF EXISTS`，可重复执行；无外键约束（关系以业务字段软关联），建表顺序无强制依赖。
4. **全文索引与中文**：多张表建有 `FULLTEXT`，MySQL 默认分词对中文效果有限；如需中文全文检索，建议改用 `WITH PARSER ngram`。
5. **应用连接配置**：后端读取环境变量 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME`，迁移后改这些即可。
